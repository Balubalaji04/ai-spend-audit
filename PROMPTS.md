# Prompts

## Overview

SpendScope uses two different approaches for recommendations vs. narrative. The **audit engine** (`src/lib/auditEngine.ts`) applies hardcoded business rules to every tool — no LLM involved. Savings amounts, downgrade logic, and redundancy checks must be predictable and testable; users are making financial decisions based on the output, so “creative” model behavior would be a liability. **AI is used only once**: the short personalized summary paragraph on the results page, generated by Claude via `POST /api/summarize`. That layer adds tone and synthesis; it never changes the numbers.

---

## Prompt 1 — Audit Summary Generator

**Endpoint:** `POST /api/summarize`  
**Model:** `claude-sonnet-4-20250514`  
**Max tokens:** `300`  
**Source:** `src/app/api/summarize/route.ts`

### The Full Prompt

**System prompt:**

```
You are a concise financial advisor helping startup founders optimize their AI tool spending. Write in a friendly but professional tone. Always be specific with dollar amounts. Never use vague language like "significant" without a number.
```

**User prompt** (values are filled in at runtime from `AuditResult`):

```
Write a 100-word personalized audit summary for this team:

Team size: {teamSize} people
Primary use case: {useCase}
Current total AI spend: ${currentSpend}/month
Potential savings identified: ${totalMonthlySavings}/month (${totalAnnualSavings}/year)
Top recommendations:
1. {recommendedAction} — {reason}
2. {recommendedAction} — {reason}
3. {recommendedAction} — {reason}

Write 2-3 sentences summarizing what the audit found. Then 1-2 sentences on the most important actions to take first. End with one sentence on the annual impact. Do not use bullet points. Total length: exactly 90-110 words. Be specific with the numbers. Write in second person (you/your).
```

The top three recommendations are the highest-savings items from `result.recommendations`, sorted by `estimatedMonthlySavings` descending.

### Why I Wrote It This Way

- **Why second person (you/your):** More personal — it reads like advice to the founder viewing the page, not a report about “the team.”
- **Why specify exactly 90–110 words:** Prevents rambling and keeps the summary readable in one glance inside the `AuditSummary` card.
- **Why mention specific dollar amounts in the system prompt:** Without that constraint, the model defaults to vague language like “significant savings” instead of repeating the audited figures.
- **Why end with annual impact:** Annual numbers feel more motivating than monthly alone and mirror the hero’s annual savings line.

### What I Tried That Didn't Work

- **First version didn’t specify word count** → Output was 200+ words, too long for the card.
- **First version used third person** → Felt clinical, not personal.
- **First version asked for bullet points** → Looked messy in the UI (the prompt now explicitly says “Do not use bullet points”).

### Fallback Strategy

The user always sees a summary. If the AI path fails, a **template fallback** is used instead (server-side in the API route, and again client-side in `AuditSummary` if the fetch fails).

**Server (`src/app/api/summarize/route.ts`)** uses the fallback when:

- The Anthropic API throws (network error, invalid key, rate limit from Anthropic, etc.)
- The response has no text block (`message.content[0]` is not `type === "text"`)
- The text block is empty (falls through to `buildFallbackSummary`)

**Client (`src/components/AuditSummary.tsx`)** uses the same template when:

- `fetch('/api/summarize')` is not `ok` (e.g. HTTP 429 rate limit from our API)
- The JSON body has no `summary` field
- Any network or parse error in the `try/catch`

**Fallback template** (dynamic values inserted from the audit):

```
Your AI spending audit identified {N} optimization opportunities worth ${monthly}/month. The biggest win is to {top recommendation action} — {top recommendation reason}. By implementing these changes, your team could save ${annual} annually — capital better invested in growing your product.
```

If there are no recommendations with savings &gt; 0, the middle sentence becomes: “Review the recommendations above for specific actions.”

The UI labels this with **(template)** next to “AI-Generated Summary” when the client used the local fallback. The fallback fills in the same key numbers (opportunity count, monthly/annual savings, top action) so the user still gets useful information even without the AI.
